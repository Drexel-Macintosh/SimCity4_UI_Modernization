# LESSONS — 2026-08-16/17 (the #176 → #182 session)

Seven lessons, each with the cost that minted it. Mechanisms and full evidence
live in `_tests\REGRESSION.md` (#176 root cause → #182) and
`tools\research\SC4-UI-ENGINE.md` §2.6; this file is the transferable part.
Written 2026-08-17, same session, per the docs-are-the-SDK standing order.

## 1. ⭐ THE LATCH LAW — a latch computed from live geometry is a hidden consumer of that geometry

`cIGZWinBMP::SetImage` (0x9BC57E→0x9BC447) derives the live `imagerect` from
the window's area AT BIND TIME; `SetArea` never refreshes it; the draw is
dst-follows-src off the latch. Resizing a window does not resize what was
derived from it. **Ask WHEN content was BOUND, not what the geometry is now** —
the geometry probe reads correct (DRAWPROBE: 153x17, exactly proportional)
while the latch stays stale.

**Cost:** five dead attributions on #176 (the #175 smoothing, the CellUnit
snap, cSC4WinAuraBar tiling, "imul 7 is the pitch", "window/crop wrong"),
three art changes that could never have moved the symptom, and a month of
misread sessions. The cure (RELATCH, v3.0.1) is ~40 lines; finding WHERE to
ask cost the day. Corollary already paid for twice: #130's arrow anchors
([ctl+0x378]) are the same shape.

## 2. A RACE explains "worked for a month" and "broken now" SIMULTANEOUSLY

The handler's first bind beat the city sweep by 0.3–1.8 s in **every one of 61
captured sessions** (08-13 → 08-16, every tier); a sim rating tick (~once per
sim month of running time) re-ran SetImage and healed it. So playing sessions
looked right and paused inspections looked broken — **at every tier**. The
"2x works / 1.5x broken" tier split was never real: both of the day's 2x
checks got a tick at +5–12 s; the 1.5x verdict session (174827) got exactly
one firing and then 75 s of silence.

**The lesson:** when two contradictory observations are both trusted, stop
adjudicating between them and look for the mechanism that makes BOTH true —
here, tick timing. It took 61 session logs to settle; no number of additional
single observations would have. Bonus trap from the same dig: "v3.0.0 worked
at 1.5x" was never an observation at all — 1.5x was not launched between
08-13 17:39 and 08-15 10:38 (deploy-log census).

## 3. TWO BLIND INSTRUMENTS DISAGREEING — the deeper measurement wins; alarm language is not evidence

A deploy-diff read the 19:42 SelectiveArt-15x fill raster as **"POISONED —
573/5967 px changed, colorkey painted opaque, alpha stripped"** and blocked
the #176 eyes-on. The corpus audit then **byte-reproduced** the same raster
from `redraw_ladder.py` — it was the deliberate #180 ladder re-lay (566/566
sheets censused, near-key 0 corpus-wide, ct=2 matches the 1x source). Not
damaged; the alarm's instrument was shallow (pixel-diff vs an era, no model of
the intended transform).

**Cost:** an evening, plus the fright itself. **The real exposure was the
inverse of the alarm** — a corpus rebuild would have silently UN-shipped #180
— closed by wiring `redraw_ladder.py` into `Rebuild-Corpus.ps1` as an
unconditional post-step. The word "poisoned" in a report carries zero
evidential weight; the byte-reproduction carries all of it. Sibling of the
standing law "two blind instruments agreeing = one".

## 4. A GATE THAT RUNS ON ONE OF TWO EQUIVALENT PATHS PROTECTS HALF THE INSTALLS

#182: `SyncStaticLayers` — the ONLY caller of per-package tier gating — ran
only under AutoScale. This rig is manual (`AutoScale=0`), so the first-ever
UncoveredIcons package deployed 2x-active by pattern and **no boot ever
swapped it**; the #149 scan then counted the icon COVERED and stood down its
runtime cure; the 352-wide 2x strip served at 1.5x (Notre-Dame's icon shifted
right, wrong hover). Zero `ScaleTier` lines in the whole session log was the
proof (law 54). Fixed v3.0.2: gate is now `(AutoScale || tierActive)`.

**This is the #149 scan's own lesson, verbatim, second instance.** The
codebase already carried the warning — `src\SC4UIScaleDllDirector.cpp`
(the `ScanUncoveredIcons` call site):

> `// #149: OUTSIDE the AutoScale branch, deliberately. The scan`
> `// depends only on the FACTOR, never on how the factor was chosen.`
> `// It used to ride inside SyncStaticLayers and therefore inherited`
> `// that function's AutoScale gate, so AutoScale=0 - a supported`
> `// user setting - silently turned the uncovered-icon cure off.`

The same trap bit the OTHER direction (package sync instead of icon scan).
**A cure gated on HOW the factor was chosen instead of WHAT the factor is
will fail on the path that chooses it the other way.** When adding anything
to a boot path, enumerate the paths that reach boot and name which ones run it.

## 5. PRESERVE THE LOG BEFORE THE NEXT LAUNCH DESTROYS IT (#105's law, re-paid)

The game's log lives at ONE fixed path and every launch overwrites it.
`Deploy-OnGameClose.ps1:39-54` carries the law and its precedent ("#105/#107:
PRESERVE THE LOG BEFORE THE NEXT LAUNCH DESTROYS IT" — the run-14 SPINPROBE
capture, the only recording of the spinning shutdown, was destroyed exactly
this way) and `Set-StockCompare.ps1` has `Preserve-Log` (:79, called :131).
**`Set-Tier.ps1` has no preserve step**, and neither does a bare game
relaunch — so this session's post-batch ThinBlt hairline capture (the armed
passive capture the 22:31 batch entry lists as "eyes-on owed", reported ~40
thin blits against the NEW art) was overwritten before it reached
`_tests\captures\`; the next surviving run (08-17 08:23) reads a 0-thin
heartbeat. The only preserved 40-thin capture (08-16 08:42) predates the
corpus rebuild, so it cannot answer the post-batch question.

**The rule:** any script or manual sequence that can trigger a relaunch is a
capture-destroying path and needs the preserve step — copying it in only the
deploy script protects only deploys. Preserve FIRST, then flip, then launch.

## 6. THE REVIEWER-VS-IMPLEMENTER LOOP — verify findings in BOTH directions

The adversarial review of RELATCH found **three real defects**, all fixed
before deploy (`REGRESSION.md` "#176 — CLOSED"): (a) composition with BMPRECT
— two crop rewrites in the kCityDialogIds pass would double-scale; (b) the
false-positive surface of the bare signature — **577 of 877 authored .UI
imagerects are full-area-at-origin, 34 of them the top-left cell of a larger
sheet**, so `crop == (0,0,oldW,oldH)` alone would expand authored crops and
drag neighbour art in → the cure became per-root arming under
kAlwaysScaleCityIds; (c) edge/9-slice windows carry slice geometry in the
rect → excluded by the same flag-bit test BMPX uses.

**Both directions matter.** Finding (b) was itself accepted only after the
577/877 census MEASURED it — and review findings also get rejected the same
way: a reviewer's confidence is not evidence in either direction (the standing
order: reviewers produce real findings AND confident nonsense; say which ones
you rejected and why). The working loop: reviewer names the hazard →
implementer measures it against the current code → the measurement, not the
argument, decides. A review finding acted on unmeasured is the same class of
defect as an alarm believed unmeasured (lesson 3).

## 7. DERIVED LISTS NEED A ZERO-INPUT REFUSAL — a CODE_BOUND table quietly defeats the empty-list guard

The #176(b) fix put a `CODE_BOUND` table (the TrendBar fill, states=6, byte
evidence inline) INSIDE `find_cell_strips.py` — which made the emitted lists
**never-empty**, so `Rebuild-Corpus.ps1`'s missing/empty⇒throw guard could no
longer prove the derivation ran: a run that read zero scripts (an unreachable
`UI_DIRS` is enough) would exit 0 with 1-entry lists and silently un-ship
#156/#177 at the next corpus rebuild. Cured in the same file
(`find_cell_strips.py:186-202`): FATAL on zero scripts read and FATAL on zero
strips derived, BEFORE the merge.

**The general form:** an empty-output guard tests the OUTPUT; appending any
constant rows moves the failure it was catching out of its sight. Guard the
INPUT census (files read, nodes derived) — same family as #181's "zero sheets
scanned is a REFUSAL, not a pass".
