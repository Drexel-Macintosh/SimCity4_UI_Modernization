The finding that matters most

Target #11 was costed at "find the selector, build one test archive." The selector turned out not to be a lookup at all.

The per-resolution .UI group is computed, every time a script loads

The project had one data point here — the stock 800×600 override set living under group 0x08000600 — and read it as a special case Maxis hard-coded. It isn't. The loader service resolves the group at 0x94B210 on every script load: read the main window's width and height, sprintf them through "0x%.4u%.4u", parse that string back as hex, write the result into the group slot, and probe it. On a miss it silently restores the caller's group.

Because %.4u is decimal and the result is re-read as hex, the rule is literally decimal digits re-interpreted as hex nibbles — and 800×600 → 0x08000600 falls straight out of the formula, which is the built-in positive control that it was derived right.

  • Arbitrary resolutions are first-class. A archive carrying scripts under 0x24001600 is picked up automatically at 2400×1600 and ignored everywhere else. Per-resolution layouts are shippable with zero runtime rewriting — a real architectural alternative to tier packages plus a scaling pass.
  • Recorded, deliberately not acted on. That is a design decision about what the mod should be, not a defect to fix, and it belongs to whoever makes it — not to a sweep.
  • The trap is the graceful part. The fallback is per-instance and silent: a resolution-specific script that is missing, or misfiled by a single digit, degrades to the default layout with no log line and no error.

Shipped · v4.6.0The engine reference is now a published section

The corpus this page maps stopped being an internal pile and became part of the repository: a front-door status document, the SDK-style engine reference behind it, and the laws distilled from real defects. The _incoming/ drafts — 430 KB of unverified agent output that had sat in a public tree with a warning only in its folder README — were adjudicated and retired, 121 claims at a time, with the survivors folded into canon and the rest deleted rather than left to be mistaken for reference. They are not to be restored.

Found by reading a logA patch family that had never once applied

The user said a launch looked fine. The log disagreed: two appliers were writing the same constant, and the second refused because the first had already changed it. The refusal was not the defect — the verifying loop is all-or-nothing and bails on the first mismatch, and this constant was second of five. So none of the five was ever written, on any boot, at any scale, for as long as both shipped. The proof is an absence: the family's success line appears zero times in a 446-line log.

The sharper halfThe two rules were never the same rule

One applier wrote a raw product, the other a rounded one. They agree at 2× and 3× by arithmetic accident and diverge at 1.5× — where the raw value is the exact number this project had already A/B-proved makes a readout vanish, with the rounding recorded as the cure in the table's own comment. The redundant writer was writing the known-bad value first and then blocking the known cure. The user runs at 2×, which is precisely why nothing ever looked wrong.

GateA check that asks what registration cannot

Both of that day's defects had one shape: an address typed as a bare literal inside a function, where the anti-rot sweep — which can only notice a family somebody named — was structurally blind. Nobody forgot to register the second one; there was nothing to register. The new check asks instead whether every address we write to resolves through a name at all, and reads the larger source file the gate had never opened. Tuning it was the work: 16 hits, 14 false, three measured refinements to 2 — a check that cries wolf gets ignored.

MethodThe gate was made to fail before the code was fixed

The collision above was invisible for two independent reasons, and fixing either alone leaves the gate green — measured, not assumed. So the order was: widen the check, name the hidden writer, watch it go red on the real address, and only then delete the redundant code and watch it go green. A gate change that goes straight to green teaches nobody that it works.

Ported too lateA gate that crashed instead of running

An arming check died before its first assertion under one common invocation form, while working perfectly under the one written into the runbook — correct for the person who wrote the command, a stack trace for anything automating it. The cure was already written down in a sibling file in the same folder, where the same trap had once silently written output to the wrong directory. Found once, documented, applied to exactly one script.

Mis-framed, then closedThe "opaque window factory" was the font registry

What is being attacked now

Everything this section used to list as owed or launch-blocked has landed. The work moved from reading the binary to watching it run — and the instruments turned out to need more debugging than the game did.

Live overlay attribution: three confirmed, one refuted, five to go

A hook on the engine's named-effect spawn was run against real play sessions with a windowed census. It settled four of the nine in-world overlay rows — three of them confirmed on screen with exact return addresses, and one refuted outright, which is the more valuable result because it redirects future work instead of consuming it.

  • Confirmed, and the static decode was right to the byte. The service-radius circle, the lot direction arrow and the drag grid all spawn as named effects. Two return addresses had been predicted from disassembly months earlier and both were hit exactly. The census also found a third spawn path in the radius family that no decode had named.
  • Refuted: the terrain-brush circle is not a named effect at all. Measured in an unfounded city with brushes actively in use across five census windows: every name logged was ambient. That row's documented attribution is wrong, while the same attribution stands confirmed for its three neighbours — a precise correction rather than a collapse.
  • Five rows remain, and two offline lanes are running against them now: the neighbour connection plates, the commute trace, both U-Drive-It route visuals, and the query/demolish hover glow.

When the instrument is the thing that is broken

Four play sessions produced one measurement. The first three measured the probe itself — and each failure arrived looking exactly like a finding, which is the whole reason the last one's control matters.

Round 1A budget raised on a branch that never ran

The census logging budget was raised and a session played: zero tool-cursor names. That zero was worthless. The census sits behind a second switch — a mode flag left at its default — so the branch never executed. Two keys had always controlled one instrument and nothing said so. Worse, the proof that the hook worked was already banked in the captures folder from twelve days earlier; checking the arming against that control was free and I did it after spending the session rather than before.

Round 1bArmed correctly, and still blind

Mode correct, 401 lines logged — and 381 of them industrial smoke. The budget was exhausted 88 seconds before the player picked up a tool. Nothing about how that session was played could have captured the target. The fix was not a bigger number: ambient effects are continuous and eat any budget. The budget had to bound distinct names, which turns the same session into 14 lines instead of 401.

Round 2An absence that was never about the instrument

The user identified what three rounds of tuning had missed: god-mode terraforming requires an unfounded city, and every session so far ran in a founded one. The brush could not have been on screen. My reasoning about that row had argued from instrument headroom — true, and entirely beside the point. Before tuning an instrument to explain an absence, ask whether the thing could have happened at all.

Round 3The one that could support a null

Unfounded city, brushes used for a minute across five windows, ten census lines, all ambient. What makes it a measurement rather than a shrug is that the positive control is internal to the same run: the hook logged a cloud spawn in every one of the five windows, including those with the brush on screen, using ten of a four-hundred budget. Awake, unsaturated, and logging — and it saw no terrain effect.

Caught within one sessionA shared name is not a shared call site

An earlier unwindowed round recorded one effect name and paired it with a neighbour as "the drag pair". The windowed run showed the drag actually uses the same name from a different caller; the first address belongs to some other consumer entirely and is still unnamed. That pairing was inferred from a name in a session with no way to tell when anything fired, and it survived one write-up before the next round contradicted it.

The standing lessonThe regression net now covers the instruments

Each of these failures reported success. The distinct-name rule was proven offline against the real capture — replaying the failing session's own name sequence — before another play session was requested, and that replay is now a permanent test. A broken instrument is not a quiet failure mode; it is a confident one.

The board is fully attributed

Two offline workflows closed the remaining five overlay rows and named the last unidentified caller. Nine rows, nine statuses — the first time the census has had no blanks.

One file already in the repository closed the same question for five rows at once

Every lane independently reached a "no such effect name in the executable" null, and every one of them was insufficient. A name the live census had already confirmed is provably absent from all 7.8 MB of the executable — because effect names can come from game data, so scanning the binary can never refute a content-driven spawn.

The loophole was closed with a dump that had been sitting in the repo the whole time: 1,148 effect names, with 13 of 13 recall on the live-confirmed set including the data-only member the executable scan misses. Against that control, the negative sweep is meaningful — route, commute, traffic, trip, path, trace: zero. Brush, terraform, circle, ring: zero.

  • Five rows refuted on that channel in one pass, at zero session cost, and the terrain-brush result measured on screen last week independently corroborated.
  • The neighbour-connection arrows are a world object, not an overlay — sized in model metres, with no screen-space constant anywhere on the path. That means correct at every scale by construction: the same verdict the zots got, reached by a completely different route, and probably no fix needed at all.
  • The drive-mode guidance arrows can be tested with a lever that already ships. The byte chain was reproduced link-for-link by the verifier, and the test drives the renderer's own removal call — nothing written, and the expected result is an absence that cannot be misread as "no change".

Two experiments that would have wasted a session

Both were caught by the adversarial pass before anyone launched the game — which is the only reason they are curiosities rather than another entry in the section above.

Wrong directionA gate claim that breaks the control run specifically

A lane stated the probe key needs a second setting to arm. It does not — and that second setting is forced off at the baseline tier, so following the instruction would have armed nothing in exactly the configuration the 1× control run requires. The conjunct had been deliberately removed earlier the same day for that precise reason. An error that breaks only the control, and leaves the experiment itself looking fine, is the worst shape available.

Not equivalentA shortcut that skips the thing being measured

A cheat code was offered as a stand-in for entering drive mode, on the strength of a byte-verified chain showing it creates the right object. But creating the object is not the registration — that lives in an initialiser the cheat path never calls. A null taken that way would have been uninterpretable: exactly the failure three earlier play sessions were spent on.

Cannot distinguishA test whose two outcomes both fit both answers

"If the dots are hidden behind a building it's a ground decal; if they draw over it, it's a billboard." Both outcomes are reachable from both channels depending on one depth setting. It measures depth state and reports it as channel — dropped rather than run.

Asserted, never measuredA liveness control that isn't one

"The marks are on screen the whole time you're driving, so every window carries its own proof of life." The bright path only fires for visible cells matching the current tiles — point the camera away from the car and a perfectly healthy instrument goes silent. A control has to be derived, not assumed, or it certifies nothing.

18 overclaimsThe label, not the fact, was usually what was wrong

The dominant refutation was a confidence grade: "proven from bytes" stamped on a link that was inference, on a row whose own findings called the subject unresolved, and on a table whose contents appeared nowhere in that row's evidence. Also several addresses cited one byte before the string they name — the push operand rather than the literal, which is the same instruction-versus-operand distinction this project keeps paying for.

Named as suchA census that proves nothing, and says so

A sweep of the game's art archives for route-dot textures found 36,388 entries of which only 2.3% carry a readable name; the rest are compressed and invisible to the method. Reported as a structural null rather than as an absence — a scanner blind to its own subject returns a clean, confident, meaningless zero.

What verification actually caught

Every lane was paired with an adversarial verifier told to refute it and to treat any claim it could not re-derive as unproven. That pass rejected 16 claims across five lanes — including one I had already written into the docs.

My errorA correction that made a doc worse

A lane reported that one size constant was shared by six indicator categories. I believed it, and "corrected" a long-standing note that had attributed the constant to a single category. The verifier refuted the lane; a hand check of every write to that field settled it. The original note was right, my correction was backwards, and the blast radius of touching that instruction is one visual, not six. Reverted, with the full derivation now in place so it cannot be re-widened.

The dominant failureOff-by-one-function attribution

The single most common refutation, by a wide margin: "site X lives in function F" where F is the function before the real one. Functions in this binary are small and adjacent, so landing one boundary early is the default mistake — and it silently reassigns behaviour to the wrong owner. Nine refutations were this shape. The rule now: never claim an enclosing function without proving both its padding-preceded entry and its terminating return.

Under-countingA too-narrow byte filter reads as absence

My own first sweep for writes to a field found three where there are four, because the pattern I matched covered one register encoding and the missing write used another. A search that is narrower than the thing it is searching for returns a clean, confident, wrong answer. Exhaustive sweeps now enumerate every store form and every register encoding.

Also caughtTwo claims of novelty that weren't

A lane announced it had found a window's creation site "previously unknown" — the repo had already documented it in two places. Another corrected a doc line that needed no correcting. Novelty claims are cheap to make and cheap to check; check them.

Already answeredAn open question the source had closed months ago

#27, the "unknown flyout with no script", is a dead branch: the code asks the loader for a script Maxis never shipped, so nothing can resolve — and the opener it uses is one we already hook. All of that was sitting in a source comment, with its own positive control, since the release that hooked that opener. The register listed it as open anyway and a research lane was spent rediscovering it. Re-derived independently at wider reach (zero hits across 1,303 script bodies and 279 archives, against controls that do hit), which is how the duplication surfaced. Instrument trapA scan that reported zero because it looked in the wrong place

A scan of nothing returns a clean zero that is indistinguishable from a real absence. Caught it because "no plugin declares this" was too convenient an answer. The project's shipped tooling already resolves this correctly; only my throwaway script didn't. Both traps are now written into the promoted instrument.
