WHAT HAPPENED TODAY (2026-08-20)
The in-game Graphic Options selector (scale + resolution + window-mode
panel injected into the game's own dialog) had a multi-second freeze on
selection changes. Two fixes had shipped on inference and missed, so
v3.13.2 shipped a pure-measurement build instead: in-memory timing buckets
(PerfProbe, src/Logger.h) with frame-gap and pass watchdogs. ONE launch
named the cause:

  SELPERF pass took 3266ms. In-pass: sel.buildResList=3264ms/1

EnumDisplaySettingsW itself costs 3.3 SECONDS on this machine (dgVoodoo
sits between us and the driver), and the once-per-session enumeration ran
on the first click. Every popular theory measured innocent: the OneDrive
logger (361 writes = 7ms), the message path (13,203 messages = 6ms), the
window-tree walks (1.3ms). The same launch also proved a second defect:
"SELRES built 0 row(s) for Windowed" — SelBuildResList had NO WINDOWED
BRANCH AT ALL (Borderless returns early, Fullscreen has its block, Windowed
fell through both to an empty list — that was the user's "empty drop list"
screenshot).

v3.13.3 (deployed 11:25:36, commit ad37a3b) cures both:
1. The enumeration now runs on a background warm thread kicked at DLL load
   (UiSpike::WarmSelectorCaches from the director constructor, tri-state
   gSelEnumState handshake) — the first click finds the cache warm. The
   user explicitly directed this design.
2. A real Windowed branch: familiar sizes that fit the desktop, EXCLUDING
   the desktop-equal size (a desktop-sized window overflows the screen once
   its title bar exists; that job belongs to Borderless).
